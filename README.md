# After Motion (v0.1.52)

**v0.1.52 (zip v97) - Export with two or more media layers showed only the background.**
- **Cause:** a project with more than one video / photo layer (or a layer that overlaps another or does not start at 0:00) is exported by the Media3 compositor (`VideoExporter.startMedia3`). The composition was built as `[canvas colour, bottom layer, ..., top layer]`, but Media3's `DefaultVideoCompositor` draws the FIRST input on TOP and each later input beneath it (its own doc: "the first registered source is on the very top"; the first sequence is also the primary one). So the opaque canvas-colour picture was drawn over every media layer and only the background came out. The lane order was upside down too.
- **Fix:** the compositor inputs are now stacked top-down: input 0 = a fully transparent picture for the whole length (covers nothing, and as the primary input it is the clock of the output frames), inputs 1..N = the media layers, TOP lane first, last input = the opaque canvas colour (very bottom). `LayerCompositorSettings` (per-layer opacity / keyframed opacity) uses the same input order. The lowest media layer still blends / fades onto the canvas colour by itself, exactly as before.
- **Diagnostics:** logcat tag `VideoExporter`, new line `EXPORT_DIAG compositor stack (input 0 = top): ...` (number of layer inputs, the alpha of every input, how many layers are blended by effect) next to the existing `EXPORT_DIAG layer[i]` lines.
- **Unchanged:** a project with a single media layer is still exported by the native C++ engine; two or more media layers stay on Media3 (`NativeProjectExporter.unsupportedReason`) until native multi-source decoding is verified on devices.
- **Also in v0.1.52 - Transform of media layers in the export.** Position / scale / rotation / pivot (also keyframed and tracked) of video and photo layers were drawn only in the preview; the export ignored them. New `engine/LayerTransform.kt` (`layerPose`, one formula for both exporters): the native C++ path passes it to `LayerParams` (offset / scale / rotation, per frame via `renderAt`), the Media3 path adds `LayerTransformEffect` (a `MatrixTransformation`, last effect of the layer). A project with a transformed layer is never exported as a plain sequence any more (the canvas colour is needed behind it). Not yet: 3D rotation / warp, and upper layers that use a blend mode (`VideoLayerBlendEffect`) ignore the transform.

### Layer system (lanes) — Alight Motion style
The timeline is a list of free lanes (lines). **One layer per line** — layers never sit side by side.
A new layer always gets its own lane on top. There is no limit on the number of lanes and no fixed
media/text/shape row. Lanes disappear when they become empty. The top lane is drawn on top.

**Layer handling:** long-press a layer on the timeline, then drag horizontally to move it in time
or vertically to reorder stacking (bring forward / send backward). Swipe the empty timeline area to
scrub with inertia.

**Export rule (v0.1.15):** Export works as soon as **any one layer** exists (video, photo, shape,
text, audio, …) — same idea as Alight Motion. If there is no video/photo media, a solid black
background of the project duration is used so the export still produces a valid MP4 (shapes/text
are still preview-only and not yet burned into the export).

## Offline motion tracking improvements (v78)

The offline circle/point tracker in `engine/LkTracker.kt` now estimates a robust similarity transform from tracked Shi–Tomasi features. A deterministic pair-hypothesis consensus fit rejects outlier/background feature motion, then least-squares refinement estimates translation, rotation and uniform scale. The selected centre and radius follow that transform, and the existing forward/backward LK validation, patch appearance check and feature reseeding remain in place. This is a lightweight Kotlin implementation with no network or model download requirement; it is not a claim of parity with Tracket Motion and should be validated on real footage/device performance.
